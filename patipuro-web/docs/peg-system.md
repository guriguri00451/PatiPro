## 2. 釘の配置レイアウト

盤面サイズは **400 × 600 px**。釘の種類は大きく3つ。

### 2-1. 外枠マイクロペグ

盤面の外周を囲む小さなペグの連続配置。壁代わりに使うことで、玉が滑らかに転がる。

| 部位 | 配置範囲 | 間隔 |
|------|----------|------|
| 左大外壁 | y: 600 → 120 | 8px 間隔 |
| 打ち出し内壁（発射レーン） | y: 600 → 200 | 8px 間隔 |
| 天井ドーム | 半楕円: 中心(200, 190), 幅±195, 高±180 | 0.04rad 刻み |
| 右大外壁 | y: 190 → 600 | 8px 間隔 |

天井ドームは以下の式で楕円状に生成される。

```
x = 200 + 195 * cos(a)
y = 190 - 180 * sin(a)    (a: π → 0)
```

**物理パラメータ（マイクロペグ）**

```
半径:           1.5 × 1.2 = 1.8 px
restitution:    0.08   （ほぼ弾まない）
friction:       0.01
frictionStatic: 0.0
slop:           0.02
```

## 3. 釘の物理パラメータ

### 玉のパラメータ

```
半径:        5.2 px
restitution: 0.5     （釘との反発）
friction:    0.005
frictionAir: 0.001   （空気抵抗）
slop:        0.005
inertia:     Infinity（回転慣性無限大、安定化のため）
density:     0.004
```

### エンジンのイテレーション設定

デフォルト値より多く設定することで、高速な玉のすり抜けを防止している。

```
positionIterations: 12   （デフォルト: 6）
velocityIterations: 10   （デフォルト: 4）
```

### 速度制限

毎フレーム、全玉の速度を最大 **12 px/frame** にクランプする。

```typescript
if (speed > 12) {
    velocity *= (12 / speed);
}
```

## 4. 疲労（劣化）システム

釘に玉がぶつかるたびに `health` 値が減少し、反発係数と色が変化する。実際のパチンコで釘が曲がって弱くなる（甘釘）ことを再現している。

### health 値

| 状態 | health 値 |
|------|-----------|
| 新品 | 1.0 |
| 半劣化 | 0.5 |
| 完全劣化（甘釘） | 0.0 |

### 疲労量の計算式

```
fatigueAmount = impactStrength × 0.0008 + totalImpacts × 0.00002
health        = max(0, health - fatigueAmount)
```

- `impactStrength`：衝突時の相対速度（強い衝突で多く劣化）
- `totalImpacts`：累積衝突回数（回数が増えると劣化が加速）
- 係数が非常に小さいため、100回以上の衝突に耐えられる設計

### 反発係数の変化

```
restitution = 0.8 × health + 0.2 × (1 - health)
```

| health | restitution | 状態 |
|--------|-------------|------|
| 1.0 | **0.8** | 新品（よく弾む） |
| 0.5 | **0.5** | 半劣化 |
| 0.0 | **0.2** | 完全劣化（甘釘、ほとんど弾まない） |

### 色の変化（視覚フィードバック）

```
R = 255（固定）
G = 204 × health + 100 × (1 - health)
B = 51 × health
```

| health | 色（RGB） | 見た目 |
|--------|-----------|--------|
| 1.0 | (255, 204, 51) | 黄色（新品） |
| 0.5 | (255, 152, 26) | オレンジ |
| 0.0 | (255, 100, 0) | 赤錆色（完全劣化） |

## 5. 近接検知システム

毎フレーム、玉の位置と全釘の距離を計算して「近接フラグ（isActive）」を管理する。

```
アクティブ化:  distance < 18 px  →  isActive = true
非アクティブ化: distance > 28 px  →  isActive = false
```

18 と 28 にヒステリシスを持たせることで、境界上でのフラグの頻繁な切り替え（チャタリング）を防いでいる。

**最適化**：まず `|dx| > 28 or |dy| > 28` の場合は距離計算をスキップし、無駄な sqrt 演算を省いている。

> **注意**：現在の実装では `isActive` フラグは管理されているが、釘は常に `isStatic: true` のまま。アクティブ化しても釘が動くわけではなく、将来の「釘が動く」拡張に向けた準備である。

## 6. 衝突処理

### 二重のクールダウン機構

同じ玉と釘のペアが連続して疲労を受けないよう、2段階で制御している。

**① フレーム内の重複防止**

```typescript
collisionThisFrame: Set<"${ballId}-${pegId}">
// beforeUpdate イベントで毎フレームクリア
```

同じフレーム内で同じペアの衝突イベントが複数来ても1回だけ処理する。

**② 時間ベースのクールダウン（100ms）**

```typescript
COLLISION_COOLDOWN = 100   // ms
lastCollisionTime: Map<string, number>
```

100ms 以内に同じペアで再び衝突しても疲労を与えない。

### 最小衝突強度の閾値

```
impactStrength = sqrt(relativeVelX² + relativeVelY²)

impactStrength < 3.0  →  疲労を与えない（弱い接触を無視）
```

### 停滞した玉の強制脱出

玉が釘の上に乗って止まってしまうケースへの対処。

```
速度 < 0.32 px/frame  が  260ms 以上継続したとき：
    velocity.x += ランダム(−0.4 〜 +0.4)
    velocity.y += 1.6   （強制的に下方向へ押し出す）
```

## 7. ネズミ返し

`label: 'nezumi-gaeshi'` を持つ物体と玉が衝突したとき、50%の確率で勝ちルート・負けルートに振り分ける。

```
クールダウン: 同一玉に対して 120ms 間隔でのみ処理
勝ちルート確率: 50%
```

| ルート | ターゲット座標 | 基本速度 | 備考 |
|--------|---------------|----------|------|
| 勝ちルート | (92, 172) | 8.8 | X ジッター ±0.65 |
| 負けルート | (212, 116) | 9.5 | X ジッター ±0.9（ぶれが大きい） |

速度には `0.85〜1.20 倍` のランダムなジッターが加わる。

## 8. デバッグ機能

`D` キーでデバッグモードをトグルできる。

物理演算レンダラーの上に透明な Canvas レイヤー（`z-index: 1000`）を重ね、30FPS で更新する。

| 描画要素 | 色・スタイル |
|----------|-------------|
| 半透明オーバーレイ | `rgba(0, 0, 0, 0.15)` |
| パルス円（玉追跡） | シアン、半径が sin 波で 13〜18px に脈動 |
| 固定円（玉追跡） | シアン、半径 10px |
| 速度ベクトル | 黄色、速度値 × 3 のスケールで描画 |

デバッグパネル（右側）では FPS と玉の数をリアルタイム表示する。
FPS が 50 超なら緑、50 以下ならオレンジで色が変わる。
